### Этап 2. Семантическая доработка конвертеров (LSI + FAQ) — [ВЫПОЛНЕНО]
*Редактируется в `frontend/src/config/tools.js`.*

- [x] **Пакет A: Извлечение из PDF (высокий спрос):**
  * `pdf-to-jpg`, `pdf-to-png`, `pdf-to-webp`.
  * *Внедрено:* рендер 200 DPI (A4 ~1654×2339 px), скачивание упорядоченным ZIP-архивом, разбор многостраничных документов, адаптация под презентации и формы.
- [x] **Пакет B: Базовые конвертеры изображений:**
  * `png-to-jpg`, `jpg-to-png`.
  * *Внедрено:* разница алгоритмов сжатия (lossless vs lossy), автоматическая замена альфа-канала на белый фон в JPG, многократное редактирование без деградации в PNG.
- [x] **Пакет C: Фавиконки для разработчиков и дизайнеров:**
  * `png-to-ico`, `jpg-to-ico`, `ico-to-png`.
  * *Внедрено:* генерация мультиформатного контейнера ICO (6 слоев: 16, 24, 32, 48, 64, 256 px) со сглаживанием LANCZOS, сохранение альфа-канала прозрачности, распаковка максимального слоя в PNG.
- [x] **Пакет D: Оптимизация под Google PageSpeed (WebP):**
  * `jpg-to-webp`, `png-to-webp`.
  * *Внедрено:* фокус на метрики Core Web Vitals и PageSpeed, сжатие на 25–45% эффективнее JPG/PNG с сохранением прозрачности и чёткости.
- [x] **Пакет E: Сборка многостраничных документов PDF:**
  * `png-to-pdf`, `webp-to-pdf`, `heic-to-pdf`.
  * *Внедрено:* объединение до 20 файлов в книжный A4, сплошная белая подложка для альфа-канала, считывание ориентации камеры из метаданных EXIF Apple, целевое позиционирование под Госуслуги, налоги, визовые центры и договоры.
- [x] **Пакет F: Конвертация современного WebP в растр:**
  * `webp-to-jpg`, `webp-to-png`.
  * *Внедрено:* решение проблем несовместимости WebP со старыми версиями Photoshop, Word и принтерами (JPG), сохранение полного альфа-канала прозрачности и теней для верстки и Figma (PNG).
- [x] **Пакет G: Специфическая графика и мобильные снимки:**
  * `heic-to-png`, `ico-to-jpg`.
  * *Внедрено:* lossless-распаковка снимков iPhone с сохранением ориентации для графических редакторов, извлечение максимального слоя иконки (до 256×256) в стандартный JPG с белым фоном.
- [x] **Пакет H: Тяжелый растр, сканы и полиграфия:**
  * `tiff-to-jpg`, `tiff-to-png`, `bmp-to-jpg`, `bmp-to-png`.
  * *Внедрено:* компрессия сканов в 10–25 раз, автоматическая конвертация полиграфического CMYK в sRGB, сохранение 100% резкости для OCR и чертежей (PNG), сжатие устаревших несжатых Bitmap.

  * При перетаскивании неподдерживаемого формата (например, HEIC на страницу `jpg-to-pdf` или WebP на `png-to-jpg`) конвертер автоматически определяет расширение и предлагает в 1 клик перейти на нужный инструмент, перенося загруженные файлы без потери времени.
  * *Эффект:* Резкое снижение показателей отказов (Bounce Rate) и улучшение внутренней перелинковки.
- [x] **Кнопка «Поделиться результатом» / «Копировать ссылку»:**
  * В шапке формы и в блоке успешного завершения конвертации внедрена кнопка «Поделиться». На смартфонах открывает нативное системное меню (Telegram, WhatsApp, VK через Web Share API), на ПК копирует готовую ссылку в буфер с визуальной индикацией.
  * *Эффект:* Рост естественного вирального и прямого трафика (Direct/Social signals).

## 4. Памятка разработчика по SEO-контрактам Convefy

При любых будущих правках обязательно соблюдать заложенные правила:

1. **Лимит `<meta name="description">`:**
   * Должен быть **строго ≤ 160 символов** (включая автоматическую приписку из `describeTool`). Проверяется скриптом `verify-dist.mjs`.
2. **Контракт FAQ под Schema.org:**
   * У каждого инструмента в `SUPPORTED_TOOLS` должно быть **ровно 4 вопроса** в массиве `faq`.
   * Текст вопросов и ответов в JSON-LD обязан на 100% совпадать с видимым текстом на странице.
3. **Шаги инструкции:**
   * Массив `steps` у каждого инструмента должен содержать **не менее 3 пунктов**.
4. **Никаких мягких 404:**
   * Несуществующие страницы должны возвращать реальный HTTP-статус 404 через `dist/404.html` (настроено в `nginx.conf`).
